# BRIEF F4-03 — Починка tools/verify.sh: три дефекта гейта
**Тип:** script
**Роль:** Executor · **Модель:** по биндингу `docs/03_ROLES.md` · **Дата:** 2026-07-28 · **Автор:** Architect
**Статус:** ACTIVE

## Цель
`tools/verify.sh` перестаёт (1) блокировать выпуск proposed-ADR, (2) пропускать удаление строк
markdown-списков из ADR-лога, (3) молчать об исчезновении `prompts/reviewer.md`. После выполнения
ADR-016 считается реализованным и запрет на proposed-ADR снимается.

- tools/verify.sh — читать целиком

- docs/04_SESSION_PROTOCOL.md (§Правила применения) · docs/07_OPERATIONAL_LESSONS.md — целиком

## Входы и факты
- Дефект 1 (ADR-016, ACCEPTED, задача не выполнена): проверка 4 даёт RED на любую изменённую строку
  ADR-лога, включая законный апрув proposed и пометку superseded. Решение задано ADR-016 дословно:
  игнорировать изменённые строки, целиком совпадающие с шаблоном строки статуса
  (`^\*\*Статус:\*\*` или `^\*\*Дата:\*\*.*\*\*Статус:\*\*`); любая другая изменённая или удалённая
  строка — RED. Флаг окружения НЕ вводить.
- Дефект 2 (найден Architect 2026-07-28): проверка 4 считает удалённые строки шаблоном `^-[^-]`.
  Удалённая строка markdown-списка выглядит в диффе как `-- текст` и под шаблон не попадает,
  то есть удаление пункта списка из ADR-лога проходит незамеченным. Требуется шаблон, который
  ловит любую удалённую строку и при этом не считает служебные заголовки диффа (`--- a/`, `+++ b/`).
- Дефект 3: `prompts/reviewer.md` введён ADR-024 как обязательный артефакт метода, но в списке
  обязательных файлов проверки 1 (`tools/verify.sh:11-15`) отсутствует.
- Скрипт исполняется вставкой в интерактивный шелл Owner. Все правила `docs/07_OPERATIONAL_LESSONS.md`
  (L-01…L-04) обязательны.

## Шаги
1. Проверка 1: добавить `prompts/reviewer.md` в список обязательных файлов.
2. Проверка 4: реализовать исключение строки статуса по ADR-016 дословно.
3. Проверка 4: заменить шаблон подсчёта удалённых строк на корректный, исключив заголовки диффа.
4. Собрать таблицу тест-кейсов и прогнать её на реальном клоне: (а) чистый append нового ADR → GREEN;
   (б) правка только строки `**Статус:**` → GREEN; (в) правка строки текста ADR → RED;
   (г) удаление строки markdown-списка из ADR → RED; (д) отсутствие `prompts/reviewer.md` → RED.
5. Выдать Owner готовый к вставке скрипт правки и команду прогона. Плейсхолдеров быть не должно (К-6).

## Критерии приёмки
- Все пять тест-кейсов дают ожидаемый результат на реальном прогоне, лог подтверждён Owner.
- Ни один существующий пункт проверки не ослаблен: сравнение вывода до и после на текущем HEAD
  даёт тот же набор `ok:`.
- Скрипт соответствует L-01…L-04: без шебанга, первая строка `set +H`, один внешний heredoc,
  Python только через временный `.py`.
