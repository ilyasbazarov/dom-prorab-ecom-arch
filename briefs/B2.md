# BRIEF B2 — Track B, волна 2: сторож зависших сделок
**Тип:** черновик задачи подрядчику
**Роль:** Executor (Sonnet) · **Дата:** 2026-08-05 · **Автор:** Architect
**Служит: Ф-1 и Ф-2** — потерянное или несформированное событие 1С→CRM сегодня оставляет сделку в нетерминальной стадии молча; сторож делает это видимым и не зависит от подрядчика 1С. Без него прогон границы упирается в тихую поломку, которая по `l0-canon/project_goal.md` §2 засчитывается провалом факта.

## Цель
Написать один тикет Bitrix-подрядчику на регламентный сторож зависших сделок по уже принятому решению ADR-018. Решение НЕ переоткрывается: механизм, пороги, календарь и адресат тревог ратифицированы. Задача Executor — превратить принятое в проверяемый тикет.

## Входы и факты (не переоткрывать)
- Механизм и границы — ADR-018: сторож регламентный, на стороне CRM, с 1С не сверяется, отказ делает видимым, а не невозможным. Гарантия доставки остаётся за P-16.
- Пороги — A-04, статус ACCEPTED, семь стадий, часы рабочие кроме явно календарных.
- Календарь 08:00–21:00 ежедневно, адресат тревог и эскалация — ADR-021 п.2 (BQ-02 RESOLVED).
- Перечень стадий берётся из канона §3, а не из текстов ТЗ: три расходящихся списка ТЗ — предмет P-08.
- Стадия «Ожидает выдачи» сторожем не покрывается: её держит автоотмена 72 ч (канон §4 T4).

## Шаги
1. Выписать таблицу «стадия → порог → тип реакции → адресат» на основе A-04 и канона §3; каждая строка с провенансом.
2. Проверить сходимость с двумя принятыми цифрами: 2 рабочих часа на эскалацию нехватки (ADR-077 п.8) и 72 календарных часа автоотмены (канон §4 T4). Расхождение не исправлять молча, вынести строкой.
3. Написать тикет по форме `tasks/trackB_wave1_bitrix.md`: Проблема · Контекст · Изменение · Критерии приёмки · Трассировка.
4. В «Изменение» явно зафиксировать: пороги — параметры настройки, а не константы кода; календарь рабочих часов — параметр; выключение сторожа по стадии — параметр.
5. В «Критерии приёмки» — проверяемые сценарии по каждой стадии таблицы, с числом, а не меткой (К-28).

## Критерии приёмки
- Тикет содержит таблицу порогов по всем стадиям канона §3, ни одной пустой клетки; непокрытые стадии названы явно с причиной.
- Каждая цифра несёт провенанс: A-04, ADR-021 п.2, ADR-077 п.8 или канон §4 T4.
- Пороги, календарь и признак «стадию не сторожим» вынесены в настройки, ни одна цифра не зашита в код.
- Ни одного нового бизнес-решения: расхождение с принятым выносится строкой, а не правится.
