# BRIEF F4-07 — Платёжные сценарии: движение денег в каждой точке потока
**Тип:** analysis
**Суждение:** с суждением (ADR-029 §4): задача принимает архитектурные решения о механике
денег, формулирует и выносит бизнес-развилки, правит канон. Дешёвой сессией не собирается.
**Класс задачи:** A
**Роль:** Architect (режим A), путь чат · **Дата:** 2026-08-03 · **Автор:** Architect
**Служит:** Ф-1 и Ф-3 — Ф-1 требует корректного списания предоплаты товарной части, Ф-3
требует автовозврата через API эквайринга; ни то, ни другое нельзя заказать подрядчику,
пока движение денег в каждой точке потока не описано в каноне.

## Цель
В каноне появляется описание движения денег по шести сценариям потока заказа. Каждое
утверждение о поведении банка несёт ровно одну пометку: установлено цитатой документации
эквайера либо гипотеза с номером отправленного вопроса. Дизайн написан в двух ветках —
терминал с предварительным блокированием суммы и терминал только со списанием, — потому
что выбор между ними делает будущий ответ банка. Три бизнес-развилки, которые трек не
решает сам, сформулированы и вынесены Owner. После этого ревью целостности (F4-08) может
снимать gated-слот §7 канона, а F4-09 — писать черновики задач подрядчикам.

## Входы и факты
- Сценариев ровно шесть, перечень задан ADR-063 §1 п.4 и не расширяется: оплата;
  частичная сборка; полный отказ; отмена клиентом; возврат после выдачи; доплата при
  изменении состава.
- Карта денег в нашем потоке — `l2-registers/payment_map.md` §1, пятнадцать точек с
  провенансом. Она вход, а не предмет правки.
- Возможности банка — `l2-registers/acquiring_checklist.md`, двадцать шесть строк:
  пятнадцать «есть», две «нет», девять «в документе не сказано».
- Вердикт «есть» означает «описано в документе», а не «доступно нам»: документ описывает
  платформу, наш мерчант-контракт — её подмножество (учётная строка в docs/00_STATE.md от
  2026-08-02). Четыре вердикта прямо помечены как платформенные, а не контрактные:
  вопросы 2, 4, 6, 21 (`l2-registers/acquiring_checklist.md` §Шаг 6).
- Семнадцать вопросов отправлены 2026-08-03 (ADR-072 §2), ответов нет. Ожидание ответов
  задачу не блокирует (ADR-063 §3).
- Три факта чтения документации закреплены ADR-069 §1: двухстадийность живёт как настройка
  терминала, срок окна подтверждения задаёт менеджер банка; подтверждение на сумму меньше
  заблокированной поддержано полем AMOUNT; вызов возврата отвечает «зарегистрирована
  заявка», а не «возврат исполнен», и существует отдельный код отказа «операция возврата
  через API для терминала запрещена». Срока зачисления денег клиенту в документе нет.
- Гейт фиксации канона (`l0-canon/canonical_order_flow.md` §2) списывает 100% товарной
  части ДО вызова `/create_order`; два из трёх исходов вызова (§4 T1) оставляют деньги у
  нас без товара с обязанностью проактивного возврата (ADR-010).
- `l0-canon/business_canon.md` в репозитории отсутствует: docs/05_ROADMAP.md и §Статус фаз
  docs/00_STATE.md называют Business Canon ожидающим Business-сессии. Ссылка на политику
  оформляется словами «политика ждёт Business-сессии», без адреса файла и строк.
- `l3-external` immutable (К-3): ни один файл корпуса не правится.
- Пустой вывод результатом не является, критерий формулируется числом (К-28).

## Шаги
1. Выписать шесть сценариев именами из ADR-063 §1 п.4 дословно. Проверить счётом: шесть,
   ни одного добавленного, ни одного пропущенного.
2. Для каждого сценария заполнить: что происходит с деньгами; кто инициирует; какой вызов
   эквайринга это реализует; какой статус платежа ожидается; что видит клиент; какая точка
   карты денег ему соответствует номером.
3. Каждое утверждение о поведении банка пометить ровно одной из двух меток. УСТАНОВЛЕНО —
   вердикт «есть» или «нет» с цитатой `l3-external/md/d7_t01_acquiring_api.md@<SHA>:строки`.
   ГИПОТЕЗА — вердикт «в документе не сказано», с номером отправленного вопроса CQ-xx и
   датой отправки 2026-08-03. Третьей метки не существует; утверждение без метки — дефект.
4. Написать дизайн в двух ветках. Ветка А: терминал с предварительным блокированием суммы.
   Ветка Б: терминал только со списанием. Для каждого из шести сценариев показать, чем ветки
   различаются и какой класс работы исчезает в ветке А. Ожидаемый результат: в ветке А класс
   возвратов «нехватка при сборке» из дизайна уходит, и третий факт границы остаётся только
   на сценарий «клиент передумал после получения» (ADR-063 §6). Выбор ветки делает ответ
   банка на CQ-15, не эта задача: обе ветки остаются в файле до ответа.
5. Отдельной строкой завести величину «срок зачисления денег клиенту»: слот, источник —
   ответ банка на CQ-11, значение пустое. Величину не сочинять и в текст уведомления
   клиенту не подставлять (ADR-063 §1, слот варианта текста №7).
6. Сформулировать три развилки ADR-063 §7 по форме К-25: суть выбора, варианты с
   последствиями, рекомендация отдельной строкой. Вынести Owner отдельным блоком. Закрытие
   развилок в задачу не входит. Развилки: что обещаем клиенту по сроку зачисления; кто
   несёт эквайринговую комиссию при возврате; как поступаем при частичной сборке, если
   подтверждение на меньшую сумму нам недоступно.
7. Оформить принятые архитектурные решения записями журнала. Каждый пункт блока последствий
   несёт маркер времени из закрытого перечня ADR-044 §1.
8. В `l0-canon/canonical_order_flow.md` §7 добавить одну строку-указатель на новый файл.
   Сам gated-слот не снимать: его снимает F4-08.

## Критерии приёмки
- Сценариев ровно шесть; их имена совпадают с перечнем ADR-063 §1 п.4 дословно.
- Утверждений о поведении банка без метки: 0. Каждая метка принадлежит закрытому перечню из
  двух значений; формулировки «вероятно», «скорее всего», «по-видимому» — дефект.
- Каждое УСТАНОВЛЕНО несёт цитату вида `файл@SHA:строки`. Цитат без номеров строк: 0.
- Каждая ГИПОТЕЗА несёт номер отправленного вопроса. Гипотез без номера вопроса: 0.
- Обе ветки дизайна описаны для всех шести сценариев; незаполненных клеток: 0.
- Развилок сформулировано: 3. Развилок, закрытых архитектором самостоятельно: 0.
- Слот срока зачисления присутствует, значение пустое, источник назван номером вопроса.
- Ссылок, ведущих в несуществующий файл `l0-canon/business_canon.md` с адресом строк: 0.
- gated-слот §7 канона на месте, не снят.
- Формулы в задаче нет (К-32).
