# BRIEF F4-19 — Разбор машинной спецификации интерфейса Битрикса (D9) против карты потока
**Тип:** analysis
**Суждение:** механический (ADR-029 §4): состав шагов закрыт ADR-105 §4, перечни входа закрыты
числами, вердикты берутся из закрытых перечней. Решений задача не принимает: спорное
сопоставление помечается и уходит наверх, а не решается исполнителем.
**Класс задачи:** A. Внесение самой спецификации в `l3-external/raw` было операцией класса B и
исполнено Owner коммитом `f81a9b1` (ADR-128 §1); эта задача `raw` не трогает.
**Роль:** Executor (Sonnet), путь Claude Code · **Дата:** 2026-08-11 · **Автор:** Architect
**Блокирует:** `F4-17` — прогон заказа по шагам карты. Прогон проверяет соответствие реального
поведения ожидаемому, а ожидаемое по стороне Битрикса задано интерфейсом: пока спецификация не
разобрана против карты, неизвестно, какие шаги вообще есть чем щупать. Через `F4-17` задача
служит Ф-1 и Ф-2 (`l0-canon/project_goal.md` §2).

## Цель
В репо появляется цитируемый текст спецификации D9 с построчной адресацией и блоком провенанса,
строка фрагмента в описи корпуса, перечень всех двенадцати операций спецификации, сопоставленный
с шагами карты `OF-NN`, и строки расхождений в регистре гэпов — в обе стороны, каждая с
адресатом. После этого на интерфейс Битрикса можно ссылаться цитатой `файл@SHA:строки`, а `F4-17`
получает список того, что подлежит прогону, и того, чего прогонять нечем.

## Входы и факты
- **D9 — источник истины по интерфейсу Битрикса** (ADR-128 §2). Провенанс лежит в
  `l3-external/MANIFEST.md` абзацем «D9 — машинная спецификация»: 120 264 байта, sha256 первые 16
  `a49c1fa8d6ccbeb7`, 3 129 строк по `wc -l`, OpenAPI 3.0.3, `info.title` «1C Data Contract»
  версии 1.2.0. **Путей 10, операций 12, схем в `components.schemas` 44, серверов 1.** Эти четыре
  числа входа берутся как данность и используются в приёмке.
- **D8 старше не становится нигде.** `l3-external/raw/1c_data_contract.yaml` — производный
  контракт обмена и снимок (ADR-128 §2, К-33). При расхождении с D9 прав D9, а само расхождение
  есть находка, а не повод править D9.
- **Перечни путей D9 и D8 уже сверены и совпали: 10 против 10, расхождений 0 в обе стороны**
  (ADR-128 §3, носитель `reference/2026-08-11_bitrix_swagger_vs_d8.md`). Эта сверка заново не
  гоняется. Границы её вывода жёсткие (ADR-128 §4): сверены ТОЛЬКО перечни путей, и утверждать
  «D8 верен» по схемам и полям нельзя.
- **Сверка схем и полей D8 против D9 в объём задачи НЕ входит** (ADR-129 §1). Вопрос заведён
  строкой открытого вопроса и закрывается отдельно.
- **Вердикт «реализовано» из спецификации не выводится ни в одной строке** (ADR-128 §5,
  ADR-105 §4, К-1). D9 описывает ЗАЯВЛЕННЫЙ интерфейс; прогон — задача `F4-17`.
- **Карта — норма, спецификация её не переписывает** (К-2). `l0-canon/order_flow_e2e.md` держит
  36 шагов `OF-01`…`OF-36` по девять полей на шаг; из полей задаче нужны «Направление», «Вызов
  или событие» и «Ответ». Правка карты запрещена: расхождение спецификации с картой есть
  находка, адресуемая Architect, изменение L0 идёт только новым ADR.
- **Ключи дельт заводятся в собственном пространстве `Д9-NN`** и нумерацию `Д-01`…`Д-14` не
  продолжают (ADR-129 §5): те принадлежат разделу §Дыры карты канона, а канон задача не правит.
- `l3-external` immutable (К-3): исходный JSON не редактируется, конвертированный md после
  коммита тоже; исправление — новый файл с новой датой.
- Детерминированное исполняется кодом, не моделью (К-26); критерий формулируется утвердительно
  и числом (К-28); вывод без артефакта не существует (К-22).

## Шаги

**1. Сверить провенанс источника фактически.**
```bash
wc -c < l3-external/raw/bitrix_swagger_2026-08-11.json
wc -l < l3-external/raw/bitrix_swagger_2026-08-11.json
shasum -a 256 l3-external/raw/bitrix_swagger_2026-08-11.json | cut -c1-16
```
Ожидание: 120264 · 3129 · `a49c1fa8d6ccbeb7`. Любое расхождение — стоп и Architect, объяснения
самостоятельно не строить.

**2. Конвертировать спецификацию в цитируемый md.** Конвертация детерминированная, порядок
ключей источника сохраняется, содержание не пересказывается:
```bash
python3 - <<'PY'
import json, hashlib
src = 'l3-external/raw/bitrix_swagger_2026-08-11.json'
dst = 'l3-external/md/d9_t01_bitrix_api_spec.md'
raw = open(src, 'rb').read()
spec = json.loads(raw.decode('utf-8'))
methods = ('get', 'post', 'put', 'patch', 'delete')
ops = sum(1 for p in spec['paths'].values() for m in p if m in methods)
head = [
    '# D9 — машинная спецификация интерфейса Битрикса (OpenAPI 3.0.3)',
    '',
    'Файл получен конвертацией из `l3-external/raw/bitrix_swagger_2026-08-11.json` без изменения',
    'содержания и порядка ключей. Единица цитирования — этот файл плюс номера строк (К-1).',
    '',
    '## Блок провенанса источника',
    '',
    '| поле | значение |',
    '|---|---|',
    '| исходный файл | `l3-external/raw/bitrix_swagger_2026-08-11.json` |',
    '| размер источника, байт | %d |' % len(raw),
    '| строк источника по `wc -l` | %d |' % raw.count(b'\n'),
    '| sha256 источника, первые 16 | `%s` |' % hashlib.sha256(raw).hexdigest()[:16],
    '| коммит внесения источника | `f81a9b1` (класс B, Owner, `ALLOW_RAW_CHANGE=1`) |',
    '| конвертация | `json.dumps(spec, ensure_ascii=False, indent=2)`, порядок ключей сохранён |',
    '| формат | %s |' % spec['openapi'],
    '| путей | %d |' % len(spec['paths']),
    '| операций | %d |' % ops,
    '| схем в `components.schemas` | %d |' % len(spec['components']['schemas']),
    '',
    '## Спецификация целиком',
    '',
    '```json',
]
out = '\n'.join(head) + '\n' + json.dumps(spec, ensure_ascii=False, indent=2) + '\n```\n'
open(dst, 'w', encoding='utf-8').write(out)
b = out.encode('utf-8')
print('строк:', out.count('\n'))
print('размер, байт:', len(b))
print('sha256 первые 16:', hashlib.sha256(b).hexdigest()[:16])
PY
```
Три напечатанных числа идут в отчёт и в строку описи. Собственный sha256 файла внутрь файла не
пишется — он живёт в `l3-external/MANIFEST.md`, как у D7 и остальных фрагментов.

**3. Дополнить таблицу «Фрагменты» в `l3-external/MANIFEST.md` одной строкой:**
файл `md/d9_t01_bitrix_api_spec.md` · документ D9 · вкладка `—, JSON pretty-print` · число строк
из шага 2 · sha256 первые 16 из шага 2. Абзацы провенанса D8 и D9 выше таблицы не трогаются.

**4. Выписать перечень всех двенадцати операций** в `reference/2026-08-11_d9_operations_vs_of.md`
таблицей, по строке на операцию, колонки: номер · метод · путь · `operationId` · тег · `summary`
дословно · адрес в конвертированном файле `d9_t01_bitrix_api_spec.md:строки` · направление обмена
(входящий вызов к Битриксу либо исходящий вызов Битрикса) · имена схем запроса и ответа.
Операций ровно 12, путей ровно 10; расхождение с этими числами — стоп и Architect.

**5. Разделить операции по предмету карты.** Карта следует за ОДНИМ заказом
(`l0-canon/order_flow_e2e.md` §Заголовок и §0). Поэтому:
- операция относится к предмету карты, если её предмет — конкретный заказ, его статус либо
  связанная с ним сделка;
- операция справочного или служебного обмена (товары, склады, категории, контрагенты, цены и
  остатки, получение токена) предметом карты не является: она получает в перечне пометку
  `вне предмета карты` с одной фразой обоснования и **строкой дельты не становится**.

Оба числа выписываются: сколько операций относится к предмету карты (P) и сколько вне его (Q),
P + Q = 12. Ожидание — Q = 7 (`Auth` 1, `Full Sync` 5, `Fast Update` 1) и P = 5; фактическое
расхождение с ожиданием ошибкой не является, но записывается строкой с обоснованием, а не молча.
«Вне предмета карты» не читается как «не разобрано»: адрес в конвертированном файле такая
операция получает наравне с остальными.

**6. Сопоставить операции предмета карты с шагами `OF-NN`.** Правило сопоставления закрыто:
операция сопоставляется шагу, если поле «Вызов или событие» этого шага называет тот же обмен —
совпадением пути либо имени метода (`/create_order` и подобные), либо совпадением предмета
обмена при явном указании стороны. Каждое сопоставление подтверждается цитатой
`l0-canon/order_flow_e2e.md@<SHA сессии>:строки`; сопоставление без цитаты недействительно (К-1).
Одна операция может быть сопоставлена нескольким шагам, и один шаг — нескольким операциям.
Сопоставление, которое исполнитель не может подтвердить цитатой, помечается `СПОРНО` с одной
строкой «почему сомнительно» и выносится в Return-this отдельным перечнем — не решается.

**7. Определить подмножество шагов карты, участвующих в обмене с 1С.** Шаг входит в
подмножество, если его поле «Направление» называет 1С отправителем либо получателем. Число S
выписывается; ожидание — 14 (8 шагов `CRM → 1С` и 6 шагов `1С → CRM`), расхождение записывается
строкой с обоснованием. Шаги вне подмножества в счёт M не идут и дельт не порождают.

**8. Завести строки дельт** в `l2-registers/implementation_gaps.md` новой секцией
`## §Дельты D9 (задача F4-19)`, таблицей с колонками: ключ `Д9-NN` · класс · шаг `OF-NN` либо
`шага нет` · операция D9 либо `операции нет` · суть расхождения одной строкой · адресат.
Классов ровно три, четвёртого нет:
- **A** — операция предмета карты, не сопоставленная ни одному шагу: интерфейс есть, карта его
  не описывает. Число строк класса A равно K = P − N.
- **B** — шаг подмножества шага 7, которому не сопоставлена ни одна операция: карта требует
  обмен, спецификация его не содержит. Число строк класса B равно M.
- **C** — сопоставленная пара, у которой описание в D9 расходится с полями «Вызов или событие»
  либо «Ответ» того же шага карты: другое имя, другой состав обязательных полей запроса,
  отсутствующий у карты код ответа либо отсутствующий в спецификации исход, названный картой.
  Сличение полных схем `components.schemas` в класс C не входит — сравниваются только те поля и
  исходы, которые карта называет прямо.

Адресат берётся из закрытого перечня четырёх значений: `Bitrix-подрядчик` · `List.kg` ·
`оба подрядчика` · `Architect (правка карты новым ADR)`. Пятого значения нет; не подходит ни
одно — стоп и Architect.

**9. Привязать дельты к строкам регистра.** У строк таблицы регистра, чьи шаги названы в
классах B и C, колонка «Гэп и адресат» дополняется ключом `Д9-NN` через запятую. Существующие
ключи `Д-01`…`Д-14`, вердикты строк и остальные колонки не трогаются ни в одной строке.

**10. Свести счёт** отдельной таблицей в `reference/2026-08-11_d9_operations_vs_of.md` — числа
перечислены в §Критерии приёмки, каждое выписывается, в том числе нулевое.

**11. Отметить закрытие части (2) `OQ-08`.** В строке `l2-registers/open_questions.md:30` в
колонке состояния часть (2) («где лежит описание REST-интерфейса Битрикса») помечается закрытой
с четырьмя адресами: файл `l3-external/raw/bitrix_swagger_2026-08-11.json`, абзац провенанса D9
в `l3-external/MANIFEST.md`, конвертированный фрагмент `l3-external/md/d9_t01_bitrix_api_spec.md`,
запись ADR-128 §1. Статус самой строки остаётся `OPEN`: части (1) и (3) настоящей задачей не
затрагиваются, вопрос закрывается только по всем трём. Ни один другой вопрос регистра не
трогается.

## Критерии приёмки
- Размер, число строк и sha256 первые 16 источника, полученные шагом 1, совпали с абзацем
  провенанса D9 в `l3-external/MANIFEST.md`: 120264 · 3129 · `a49c1fa8d6ccbeb7`. Расхождение — стоп.
- Строк перечня шага 4 — **12 из 12**; путей в перечне — **10 из 10**; операций без адреса
  `d9_t01_bitrix_api_spec.md:строки` — **0**.
- Схем `components.schemas` разобрано **44 из 44**: каждая несёт отметку «используется операцией
  №N» либо `не используется ни одной операцией`; схем без отметки — **0**.
- Операций отнесено к предмету карты — **P**, вне предмета — **Q**, и **P + Q = 12**.
- Операций предмета карты, сопоставленных хотя бы одному шагу, — **N**; не сопоставленных —
  **K**; и **N + K = P**.
- Шагов карты всего **36**; шагов подмножества обмена с 1С — **S** (пустым не остаётся);
  шагов подмножества без сопоставленной операции — **M**.
- Строк дельт заведено **L**, и равенство сходится: **L = K + M + C**, где число строк класса A
  равно K, класса B равно M, класса C равно C. Значение L = 0 допускается только при K = 0,
  M = 0 и C = 0, и тогда пишется дословно «дельт: 0» — пустой вывод результатом не является (К-28).
- Строк дельт без адресата из закрытого перечня четырёх значений — **0**.
- Строк дельт классов B и C, не привязанных к строке регистра ключом в колонке «Гэп и адресат», — **0**.
- Спорных сопоставлений — число выписано, в том числе **0**; каждое несёт строку «почему сомнительно».
- Утверждений о том, что подрядчик что-либо реализовал, — **0** во всех записанных файлах.
- Строк `l3-external/raw/*`, `l0-canon/*` и `docs/02_ADR_LOG.md`, изменённых задачей, — **0**.
- Строк регистра, у которых изменился вердикт либо колонки «заявлено подрядчиком» и «чем
  проверено нами», — **0**.
- Формулы в задаче нет (К-32).

## Return-this
Пути пяти записанных файлов. Числа P, Q, N, K, S, M, C и L дословно, плюс три числа шага 2
(строк, байт, sha256 первые 16 конвертированного файла). Перечень спорных сопоставлений с
пометкой `СПОРНО`. Перечень операций, помеченных `вне предмета карты`, номерами.
Плюс session-блок по `docs/04_SESSION_PROTOCOL.md` (обязателен).

## Вне scope
- Не сверять схемы и поля D8 против D9: решение ADR-129 §1, вопрос вынесен отдельной строкой.
  D8 читается только там, где это нужно для понимания расхождения, и утверждений о его
