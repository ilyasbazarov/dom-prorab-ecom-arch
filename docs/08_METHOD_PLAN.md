# 08_METHOD_PLAN — план метод-волн (разбор METHOD_OPTIMIZATION_BRIEF)

**Статус:** LIVING (правки — только session-блоком через Applier; ADR-035 §3).
**Что это:** операционный трекер внедрения решений ADR-030: гейты волн, статусы пунктов, признаки исполнения. НЕ источник решений: решения — в docs/02_ADR_LOG.md; при расхождении плана и лога прав лог, расхождение = дефект плана (ADR-035 §2). Снапшот исходного ревью: reference/2026-07-29_method_optimization_brief.md.

## Как пользоваться
1. Волна стартует только при выполненном гейте; факт старта — дата в таблице гейтов, вносится session-блоком.
2. Пункт закрывается только по признаку исполнения; смену статуса вносит session-блок очередной сессии.
3. Метод-сессия — штатная Architect-сессия (prompts/architect.md) с задачей из этого плана (ADR-035 §4). Выход штатный: развилки по К-25, решения ADR, drop-in-патчи, session-блок с JOURNAL_ROW; применение — Applier.
4. Статусы пунктов: PENDING (волна не стартовала) · ACTIVE (внедрено, признак не закрыт) · DONE (признак закрыт) · REJECTED (отклонено, см. §Отклонено).

### Порядок

Пачка A → пачка B → бриф M1-12. Пересечения файлов между A и B нет, но одновременно они не
выпускаются: параллель закрыта до волны M2 (ADR-037 §1). Бриф M1-12 идёт после пачки B,
потому что собирается по изменённому шаблону, и до Reviewer-сессии по пакету Track B
(ADR-038 §3).

Условие выпуска пачки A: ADR-044 и ADR-045 переведены в accepted. Обе записи меняют правило
метода и обе попадают под третью точку ADR-033 §2, поэтому идут одной короткой
Reviewer-сессией по форме прецедента ADR-043 §3 — одним сообщением, только по этим двум
записям. До апрува две правки пачки A неприменимы по К-15 (M1-01 опирается на ADR-044),
а пять пусковых строк пришлось бы переписывать дважды. Решение Owner 2026-08-01: пачка
придерживается целиком, а не расщепляется, чтобы состав пачки в плане совпадал с составом
коммита и чтобы ранбук rev2 (M1-06-rev2) выпускался один раз.
