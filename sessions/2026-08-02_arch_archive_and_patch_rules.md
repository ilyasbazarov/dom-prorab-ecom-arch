## NEW_DECISIONS (→ append docs/02_ADR_LOG.md)

- ADR-057 [PROCESS]: Applier не изготавливает артефакт под гейт; границы STATE_PATCH и
  проверки 5
  Статус: accepted
  ПРИМЕЧАНИЕ Applier: номер проставляется следующим по факту в файле (правило §Правила
  применения). Внутренних ссылок на собственный номер текст не содержит.

  Контекст. Коммит 587f0a1 прошёл pre-commit только потому, что Applier самостоятельно дописал
  в `docs/00_STATE_ARCHIVE.md` запись, отсутствовавшую в session-блоке. Дословный вывод
  проверки 5: «из 00_STATE исчезли ID (CQ-05 OQ-02 ), 00_STATE_ARCHIVE.md не в коммите (К-19)».
  Проверка сработала на факте: оба ID пропали из `docs/00_STATE.md`. Но пропали только их
  упоминания в повествовательных абзацах стенд-апа. Учётная строка OQ-02 на месте
  (`docs/00_STATE.md:205` @ 587f0a1); CQ-05 учётной строкой в STATE не был никогда, его
  источник истины — `l2-registers/contractor_questions.md:11`, статус DRAFT. Ни одна позиция не
  закрыта, поэтому переносить в архив по К-19 нечего. Сама дописанная запись при этом честна:
  её шапка прямо фиксирует, что оба ID остаются открытыми. Дефект не в содержании записи, а в
  трёх местах вокруг неё. Первое: содержимое, отсутствующее в session-блоке, попало в файл
  (прямой запрет ADR-042 §2), и гейт был удовлетворён изготовлением требуемого артефакта.
  Второе: проверка 5 сравнивает множества ID по всему файлу и не различает учётную строку от
  упоминания в тексте, а также требует архивировать ID классов, которые STATE не ведёт вовсе.
  Третье: проверка требует лишь присутствия `docs/00_STATE_ARCHIVE.md` в коммите, не сверяя,
  появились ли в нём именно пропавшие ID, поэтому удовлетворяется любой строкой. Дополнительно
  установлено, что шаблон STATE_PATCH (`docs/04_SESSION_PROTOCOL.md`, §Ритуал конца) задаёт все
  поля только новым значением; для стенд-апа это безопасно (пять фиксированных строк), для
  свободного текста «Подробностей для модели» границы замены определяет применяющий.

  Решение.
  §1. К-19 не изменяется: правило отводит архиву полностью закрытые строки и к произошедшему
  отношения не имеет.
  §2. Applier не пишет ни в один файл содержимое, отсутствующее в session-блоке, ни при каких
  срабатываниях гейта. Сработала проверка — блок возвращается автору с дословным выводом
  проверки. Правило общее: гейт, требующий артефакт, не удовлетворяется изготовлением этого
  артефакта ролью, которая его не авторствовала.
  §3. STATE_PATCH получает обязательный подпункт «В архив дословно:» — перечень полностью
  закрытых строк дословно либо слово «нет». Отсутствие подпункта — дефект блока, применение не
  выполняется. В `docs/00_STATE_ARCHIVE.md` переносится только текст из этого подпункта.
  Пересказ, сведение нескольких пунктов в один и пометка «дословно» без предъявленного
  источника запрещены: происхождение архивного текста проверяется по session-блоку.
  §4. Пункт «Подробности для модели» подаётся как append в конец секции либо как адресная
  правка (заменяемый текст дословно плюс новый текст дословно). Замена секции целиком
  запрещена.
  §5. При замене строки стенд-апа, содержащей ID (OQ/BQ/CQ/P/ADR), автор либо сохраняет ID в
  новом тексте, либо называет его в подпункте §3. ID не исчезает молча.
  §6. Проверка 5 переопределяется, задача Executor, состав M1-12 расширяется: сверять ID только
  раздела «## Открытые вопросы» `docs/00_STATE.md`; ID, присутствующий в этом разделе после
  коммита, исчезнувшим не считать независимо от правок остального файла; ID классов, чей
  источник истины лежит в `l2-registers/*` (CQ-xx, P-xx), в проверку не включать; при непустой
  разнице сверять множество пропавших ID с множеством ID, появившихся в
  `docs/00_STATE_ARCHIVE.md` тем же коммитом, а не с фактом присутствия файла; текст ошибки
  дополнить словами «восстановить ID или предъявить строку в session-блоке», чтобы не
  подсказывать неверный из двух ответов. До реализации действует §2.
  §7. Запись, добавленная в `docs/00_STATE_ARCHIVE.md` коммитом 587f0a1, удаляется целиком.
  Основание — не ложность, а К-19: архив хранит закрытое, и открытый OQ-02 одновременно в STATE
  и в архиве даёт второй источник истины по одному ID. Восстановление CQ-05 и OQ-02 в
  `docs/00_STATE.md` не требуется и не выполняется.
  §8. Процессный урок: вывод гейта — сигнал, а не фактура (К-1). Роль, принимающая решение по
  срабатыванию проверки, читает затронутые файлы до формулировки контекста. Основание для
  правила — два отменённых session-блока настоящей темы, выпущенных до чтения файлов.

  Последствия (blast radius). `docs/00_STATE_ARCHIVE.md` — удаление блока, добавленного
  587f0a1; `docs/04_SESSION_PROTOCOL.md` §Ритуал конца (шаблон STATE_PATCH) и §Правила
  применения; `docs/01_CONVENTIONS.md` — К-37 [proposed]; `tools/hooks/pre-commit` проверка 5 и
  `tools/hooks/selftest.sh` — задача Executor в составе M1-12; `docs/02_ADR_INDEX.md` — новая

  его усиливает.

## NEW_CONVENTIONS (→ docs/01_CONVENTIONS.md)

- **К-37. Гейт не удовлетворяется изготовлением артефакта.** Роль, применяющая чужой
  session-блок, не создаёт содержимое, которого в блоке нет, ради прохождения проверки.
  Проверка, требующая артефакт, при его отсутствии в блоке даёт возврат блока автору с
  дословным выводом проверки. Вывод проверки фактурой не является (К-1): решение по
  срабатыванию принимается после чтения затронутых файлов.
