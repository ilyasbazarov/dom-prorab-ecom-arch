## NEW_DECISIONS (→ append docs/02_ADR_LOG.md)

- ADR-056 [ARCH]: Корректировка привязки находок ADR-053/054/055 к записям Problem Register
  Статус: accepted

  Контекст. ADR-053, ADR-054 и ADR-055 приняты и применены коммитом 587f0a1. Их разделы
  «Последствия» назначали находкам ID существующих записей регистра: ADR-053 — P-30, ADR-055 —
  P-27, ADR-054 — P-17. Сверка с фактическим содержимым регистра на HEAD 587f0a1 показала, что
  назначение ошибочно. P-30 фиксирует исходное утверждение о том, создаётся ли документ при
  `partial`/`rejected`, и опровергнут прямыми цитатами (`d5_t01@8a7eedbb:1403-1409` — «НЕ
  создавать заказ. Откатить транзакцию»; `:1316-1328` — `purchase_order_guid` и
  `purchase_order_number` равны `null` при `rejected`); расхождение формата идемпотентного
  повтора в эту запись не входит и статус её не меняет. P-27 фиксирует гипотезу о паре
  `check_printed` + `order_completed` для физлица, то есть о влиянии проведения «Чека ККМ» на
  статус родительского «Заказа покупателя»; находка ADR-055 касается пары из двух подписок с
  одним событием `order_completed` для юрлица и четвёртой URL-константы, это другой сценарий,
  другие документы и другие ключи дедупликации. P-17 закрыт по исходной формулировке как
  SUPERSEDED→P-02; предложение «повтор=200 / невозможное=409» было корректно вынесено
  Executor'ом в «требует ADR» и там разобрано, статус записи оно не меняет.

  Решение.
  1. Находка ADR-053 (формат идемпотентного повтора `/create_order`) получает собственный ID
     P-33. Ссылка «новая запись P-30» в разделе «Последствия» ADR-053 читается как P-33.
  2. Находка ADR-055 (четвёртая URL-константа `CRM_Webhook_URL_OrderCompleted`, не заказанная
     Bitrix-подрядчику; два источника `order_completed`) получает собственный ID P-34. Ссылка
     «новая запись P-27» в разделе «Последствия» ADR-055 читается как P-34.
  3. Формулировка ADR-054 п.5 «P-17 закрывается как REFUTED в части «правило существует»»
     сохраняет силу ровно в названной части. Статус записи P-17 остаётся SUPERSEDED→P-02 и не
     меняется; дополняется только колонка трассировки. Ссылка «новая запись P-17» в разделе
     «Последствия» ADR-054 аннулируется: новая запись не заводится.
  4. Причинностный вопрос ADR-055 п.5 задаётся отдельным CQ-07. CQ-06 остаётся вопросом
     Executor-сессии F5-02 про «Чек ККМ» и не изменяется. Два вопроса адресованы одному
     контрагенту и могут уйти одним письмом; это операционное решение Owner.
  5. Тексты ADR-053, ADR-054, ADR-055 не правятся (append-only). Настоящий ADR — единственная
     точка корректировки.

  Последствия (blast radius). `l2-registers/problem_register.md` — две новые записи (P-33,
  P-34) и правка одной ячейки трассировки P-17; `l2-registers/contractor_questions.md` — новая
  запись CQ-07; `docs/02_ADR_INDEX.md` — новая строка. Канон, бриф F5-02 и роудмап правок не
  требуют: они ссылаются на ADR, а не на ID записей регистра.
