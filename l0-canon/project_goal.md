# PROJECT GOAL — цель проекта и граница «сделано»

**Статус:** CANON (L0). Изменения только через ADR. Основание: ADR-051, KB [3] Программа 2.

## 1. Зачем проект
Открыть Dom Prorab работающий онлайн-канал продаж: клиент оформляет заказ на сайте,
платит и получает товар (или деньги обратно) без ручной склейки систем — фундамент
позиционирования «первый профессиональный e-com DIY в КР с работающими остатками,
on-time доставкой и возвратом без вопросов».

## 2. Граница «сделано»
Проект сделан, когда на бою прошли три живых факта, каждый — с реальным клиентом и
реальными деньгами, без ручных шагов сверх перечня §7:
- **Ф-1. Заказ «карта + доставка».** Заказ с сайта дошёл до документа 1С: резерв
  поставлен, предоплата товарной части зачислена (ADR-010), списание корректно,
  платёжный документ напечатан; статусы прошли 1С↔CRM в обе стороны по маппингу;
  клиент получил WA-уведомления по ADR-021; товар доставлен в обещанный клиенту
  интервал. Видно по номерам: клиентский номер заказа, сделка CRM, документ 1С, чек.
- **Ф-2. Заказ «самовывоз + оплата на месте».** Та же цепочка; подтверждение менеджером
  ≤30 мин рабочего времени (ADR-021 п.1); товар выдан, оплата принята на месте.
- **Ф-3. Возврат.** Один живой возврат реальному клиенту на бою: деньги зачислены
  обратно на карту автовозвратом через API эквайринга (механика и SLA — по закрытию
  OQ-02). Ручной возврат через кабинет эквайринга (BQ-04) остаётся операционным
  fallback, но для Ф-3 не засчитывается. Ждём столько, сколько потребуется, пока
  сценарий не пройдёт на бою успешно.
Общее условие: расхождений между 1С и CRM по суммам и резервам после прогона нет —
«тихие» поломки, при которых клиент видит «не работает» и уходит, считаются провалом
факта, даже если системы вернули 200.

## 3. Не входит в скоуп (Phase 2)
- Автохендлер NPS #16 + DEC-52 (ADR-021 п.6).
- Транзакционная очередь исходящих 1С→CRM (OQ-03, post-MVP).
- Стабилизационный период («N дней без вмешательств») — эксплуатация после границы.
- B2B-программа; performance-маркетинг и масштабирование трафика (KB [4], отдельные
  программы; performance в любом случае заперт до unit-экономики — KB [9]).

## 4. Срок
Календарной даты нет (решение Owner, ADR-051 §4). Срок = условие-цепочка:
пакеты Track B волны 1 отправлены и приняты подрядчиками → OQ-02 закрыт (Бакай Банк)
→ сквозной прогон Ф-1…Ф-3 на бою. Продвижение по цепочке отражается в стенд-апе STATE.

## 5. Приёмка
Подтверждает Owner (Ильяс) лично. Артефакт — раздел «Чек-лист прогона» ниже, заполненный
номерами заказа, сделки CRM, документа 1С, чека и refund-транзакции по каждому факту.
Граница закрыта коммитом Owner с заполненным чек-листом.

## 6. Правило приоритета
Продуктовая работа — по умолчанию. Метод-сессия стартует только если в пусковом сообщении
названа строка «Блокирует: <продуктовый шаг>» (сторож — ADR-051 §7). Проблемы конвейера
фиксируются по ходу (STATE / регистры); периодически Owner созывает арх-сессию,
превращающую накопленное в пакет решений. Метод-работа «впрок», без названного блокера,
не запускается.

## 7. Ручные шаги, входящие в дизайн
Всё, что не перечислено здесь, при прогоне границы считается ручной склейкой и проваливает факт:
- Подтверждение заказа менеджером ≤30 мин рабочего времени (ADR-021 п.1).
- Сборка заказа кладовщиком по заданию.
- Выдача товара и приём оплаты на месте при самовывозе.
- Передача заказа курьеру / в доставку.
- Ручной возврат через кабинет эквайринга — только как fallback вне Ф-3 (BQ-04).
