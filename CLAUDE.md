# CLAUDE.md — законы Claude Code-сессий проекта dom-prorab-ecom-arch (ADR-029, пилот)

Ты работаешь в локальном клоне репо `ilyasbazarov/dom-prorab-ecom-arch` — источника истины
проекта интеграции 1С:УТ ↔ Bitrix24 CRM ↔ Bitrix CMS (Dom Prorab, Бишкек). 1С — мастер
операционной истины; CMS→1С напрямую запрещено, только через CRM. Правила — docs/01_CONVENTIONS.md;
роли — docs/03_ROLES.md; протокол сессий — docs/04_SESSION_PROTOCOL.md.

## Старт каждой сессии (обязательный порядок)

1. `git status` — рабочее дерево чистое; `git rev-parse HEAD` — это SHA сессии: зафиксируй его
   в session-блоке и используй в цитатах (файл@SHA:строки). Дерево грязное → стоп, вопрос владельцу.
   НЕ работай поверх чужих незакоммиченных правок.
2. Прочитай обязательный контекст: docs/01_CONVENTIONS.md + docs/00_STATE.md +
   docs/02_ADR_INDEX.md + docs/05_ROADMAP.md + docs/03_ROLES.md. Полный текст конкретного ADR —
   точечно из docs/02_ADR_LOG.md по номеру; закрытые строки STATE — точечно из
   docs/00_STATE_ARCHIVE.md (К-19).
3. Проверка К-20: первая строка каждого прочитанного docs/NN_*.md и этого файла = `# FILE: <путь>`.
   Не совпало → `СОДЕРЖИМОЕ НЕ ТО: <файл> — ожидалось <что>, внутри <что>` и стоп.
4. Хук установлен и РАБОТАЕТ:
   `test -x .git/hooks/pre-commit || ln -s ../../tools/hooks/pre-commit .git/hooks/pre-commit`
   затем `bash tools/hooks/selftest.sh` — ожидание «провалено 0». Любой провал → стоп, вопрос
   владельцу: сломанная проверка хуже отсутствующей (отказ тихий). До первого коммита, не после.
5. Переформулируй задачу своими словами, перечисли входы, проверь полноту.

## ★ Законы (нарушение любого = провал сессии)

- **Человеческий язык (К-16).** Правило номер один. Проза к владельцу — обычными словами; вопрос
  владельцу — только полным блоком: что решаем → варианты → векторы/последствия → рекомендация
  отдельной строкой.
- **Anti-improvisation.** Нет дока/значения/решения → `CONTEXT GAP: <что и почему блокирует>`,
  стоп, вопрос владельцу. Выдумывать, «дотягивать», подставлять правдоподобное запрещено.
- **Фактура до суждения (К-1).** Подними файл, процитируй файл@SHA:строки, потом мнение.
  SHA = `git rev-parse HEAD` этой сессии.
- **Красные линии.** l3-external/ immutable (К-3). Конфликт L0↔L3 = дефект документации
  подрядчика (К-2). Решения проекта не принимаешь: развилки — владельцу; `proposed` без апрува
  не применяется (К-15).
- **Append-only.** docs/02_ADR_LOG.md не редактируется, кроме строк статуса (ADR-016).

## Мандат (ADR-029 §2, пилот)

Ровно два режима; иные задачи — только новым ADR:
1. **«Примени session-блок»** — роль Applier: правила docs/04_SESSION_PROTOCOL.md §Правила
   применения, никакого творчества; после правок — коммит и блок «НА АРХ-РЕВЬЮ» владельцу.
2. **«Исполни бриф <ID>»** — роль Executor по prompts/executor.md; в пилоте — ОДИН бриф,
   названный владельцем.

## Конец сессии

Один session-блок по docs/04_SESSION_PROTOCOL.md — текст вставь в описание коммита.
Формат коммита: `docs: <суть> (session <id>)`. Хук обязан пройти; `git commit --no-verify`
запрещён без явного апрува владельца (фиксируется в session-блоке). `git push` не выполняется
без явной команды владельца: по умолчанию коммиты копятся локально, пуш владелец делает сам.
