# Негативный прогон проверки формы ответа (К-34, К-22)

Предмет: `tools/hooks/answer_check.sh`, введён ADR-122 §3. SHA сессии `6847d55c5d6428abda4cdeae967ab01c6d03644d`.
Дата прогона: 2026-08-10, локали C и en_US.UTF-8 (К-35) — вердикт совпал в обеих.

**Признак проверяется по ВЕТКЕ ОСТАНОВА.** Ниже дословный вывод проверки на пяти
намеренно нарушающих ответах. Положительная ветка приведена одним кейсом и удостоверяет
только отсутствие ложного срабатывания: по К-34 она признаком не является, потому что
наступает всегда.

## Команда

```
LC_ALL=en_US.UTF-8 bash tools/hooks/answer_check.sh --text <файл ответа>; echo "rc=$?"
```

Код 2 — ответ возвращён роли на переписывание. Код 0 — форма сошлась.

## Итог

Останов срабатывает на каждом из пяти классов нарушения и не срабатывает на соответствующем
ответе. Повторный заход пропускается: на один ответ приходится ровно один принудительный
переписыв, бесконечной пары «хук ↔ модель» не возникает.

Кейсы включены в `tools/hooks/selftest.sh` и гоняются на старте каждой сессии в двух
локалях, поэтому отказ самой проверки перестаёт быть тихим. Самотест на этом SHA:

```
selftest: пройдено 60, провалено 0 (локали: C, en_US.UTF-8)
```

Было 46 при 23 кейсах pre-commit хука, стало 60 при 30 кейсах: семь новых кейсов формы
ответа, из них шесть по ветке останова.
